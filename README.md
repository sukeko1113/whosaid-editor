# Gemini 文字起こし

長尺の音声ファイル(m4a / mp3 / wav 等)を Gemini API で文字起こしし、
**話者を確定させたうえで** 1 つの Word ファイル(.docx)にまとめる Windows デスクトップアプリです。

---

## v2.0.0 の変更点: 話者の決め方が変わりました

**従来(v1.3)**: 出席者名簿を先に登録 → AI が名簿を見て「この発言は佐藤さん」と推定。
→ プロンプトが長くなって処理が遅く、しかも推定はよく外れました。外れた箇所を
Word 上で直すのは、音声と突き合わせる作業になり非常に手間でした。

**v2.0 から**: AI には **声質で A / B / C … に分けさせるだけ**。実名は、
専用の割当画面でタイムラインを区間単位でたどりながら、**その区間の音声を聴いて
候補リストから選ぶ**方式にしました。

割当作業は、進めるほど速くなります。

- **確定するたびに学習** します。同じ声のまとまり(クラスタ)、会話の流れ(誰の次に誰が話すか)、
  発言頻度から、**可能性の高い話者を候補リストの先頭に持ってきます**。
- 数字キーひとつで確定 → 自動で次の未確定区間へ移動 → 自動で再生。
  マウスに触れずに流し続けられます。
- **「同じ声のまとまり全体に適用」** を使うと、1 回の操作でそのクラスタの
  未確定区間すべてを確定できます。多くの場合、これが一番速い進め方です。
- 作業状態は自動保存されます。閉じても続きから再開できます。

## 使い方

### 1. 文字起こし(メイン画面)

1. **音声ファイル**を「参照...」で選択。
2. **出力フォルダ**は既定で *音声と同じフォルダ*。
3. **API キー**を貼り付けて「保存」(初回のみ)。
4. **話者の決め方**で「区間ごとに聴いて割り当てる(推奨)」を選ぶ。
5. **出席者**を 1 行 1 人で入力(例: `佐藤(理事長)`)。
   よく発言する人を上に置くと、最初の候補順が良くなります。
   ここで入れなくても、割当画面から追加できます。
6. 「**文字起こし → 割当画面へ**」を押す。

完了すると `<音声名>.speakers.json`(作業ファイル)ができ、割当画面が自動で開きます。

### 2. 話者の割当(割当画面)

| | |
| --- | --- |
| 上部の帯 | 音声全体のタイムライン。色は話者、灰色は未確定。クリックでジャンプ |
| 左 | 区間の一覧。時刻 / 声のまとまり / 話者 / 発言 |
| 右上 | 選択中の区間の全文(その場で修正できます) |
| 右中 | 再生。区間の前後に少し余白を付けて鳴らします |
| 右下 | 話者候補。**可能性の高い順**に並び、右側に理由が出ます |

**キーボード操作**(これだけで一周できます)

| キー | 動作 |
| --- | --- |
| `Space` | 再生 / 停止 |
| `1`〜`9` | その番号の候補で確定 → 次の未確定へ |
| `Enter` | 一番上の候補で確定 |
| `↑` `↓` / `k` `j` | 区間を移動 |
| `Tab` / `Shift+Tab` | 次 / 前の未確定区間へ |
| `A` | 「同じ声のまとまり全体に適用」の ON/OFF |
| `U` | 発言者不明にする |
| `Ctrl+Z` | 取り消し |
| `Ctrl+S` | 保存 |

**おすすめの進め方**

1. まず `A`(クラスタ一括適用)を ON にして、各まとまりの代表を 1 つ聴いて確定する。
   チャンクごとに 3〜6 クラスタなので、10 分チャンク × 6 個の音声なら 20〜30 回の操作で
   ほぼ全区間が埋まります。
2. `A` を OFF にして、残った未確定・怪しい区間を `Tab` で拾っていく。
3. 「Word で出力」。

> **声のまとまりはチャンクごとに独立しています。**
> 「C1-A」と「C2-A」は別のまとまりです(AI は 10 分ごとに独立して声を聞き分けるため)。
> 候補の学習は会議全体で共有されるので、2 つ目以降のチャンクほど候補の精度は上がります。

### 3. 出力

- 「**Word で出力**」で `.docx` を生成します。
- 同じ話者の連続する区間は 1 段落にまとめられます。
- 未確定の区間は【発言者不明】として出力されます(赤字)。

### 中断・再開

- 割当作業は 4 秒ごとに自動保存されます。ウィンドウを閉じても失われません。
- 再開はメイン画面の「**保存済みの割当作業を開く...**」から `<音声名>.speakers.json` を選択。
- 文字起こし自体もチャンク単位でキャッシュされます(`.work_<音声名>\transcripts\`)。
  同じ音声で再実行すると未処理分だけが走り、**既存の割当結果も引き継がれます**。

## 詳細設定

- **モデル**: `gemini-2.5-flash`(既定 / 速くて安価) / `gemini-2.5-pro`(高精度・高コスト)
- **チャンク長**: 既定 10 分。長いほど声の聞き分けが安定し、まとまりの数も減って
  割当が楽になりますが、アップロード/転写失敗のリスクは上がります。
- **逐語モード**: フィラー・言い直しを残し、整文しません(反訳・記録用)。
- **AI にすべて任せる(従来方式)**: v1.3 の動作。名簿を AI に渡して実名まで推定させます。
  精度は落ちますが、割当作業をしたくない場合の選択肢として残しています。

## ファイル構成

```
gemini-transcriber/
├─ src/
│  ├─ main.py        ... エントリーポイント
│  ├─ gui.py         ... メイン画面(Tkinter)
│  ├─ assign_gui.py  ... 話者割当エディタ            ★v2.0
│  ├─ pipeline.py    ... 分割→転写→セグメント化の制御
│  ├─ audio.py       ... ffmpeg 呼び出し(分割・長さ取得)
│  ├─ player.py      ... 区間再生(ffplay / winsound)  ★v2.0
│  ├─ segments.py    ... 区間・話者のデータモデルと Word 出力 ★v2.0
│  ├─ suggest.py     ... 話者候補の学習・並べ替え      ★v2.0
│  ├─ transcribe.py  ... Gemini API + 出力のセグメント化
│  └─ config.py      ... 設定の永続化
├─ tests/            ... ユニット/結合/GUI スモークテスト ★v2.0
├─ ffmpeg/           ... ffmpeg.exe / ffplay.exe を置く(同梱されません)
├─ resources/        ... icon.ico を置く(任意)
├─ requirements.txt
├─ build.spec        ... PyInstaller スペック
├─ installer.iss     ... Inno Setup スクリプト
├─ build.bat         ... ワンクリックビルド
└─ README.md
```

### 作業ファイル(`<音声名>.speakers.json`)の中身

```jsonc
{
  "schema": 2,
  "audio_path": "C:\\...\\meeting.m4a",
  "duration": 3600.0,
  "speakers": [ { "id": "sp01", "name": "佐藤", "note": "理事長", "order": 0 } ],
  "segments": [
    {
      "index": 0, "start": 0.0, "end": 25.0,
      "text": "本日はお忙しい中...",
      "cluster": "0:A",        // チャンク0の「声A」
      "chunk": 0,
      "speaker_id": "sp01",    // null なら未確定
      "reviewed": true
    }
  ]
}
```

## ビルド手順 (Windows・ローカル)

### 必要なもの

| ツール | 用途 | 入手先 |
| --- | --- | --- |
| Python 3.11 以上 | アプリ本体 | https://www.python.org/downloads/ (PATH 追加にチェック) |
| ffmpeg + ffplay(static build) | 音声分割・区間再生 | https://www.gyan.dev/ffmpeg/builds/ の **release-essentials** |
| Inno Setup 6 | インストーラ作成 | https://jrsoftware.org/isdl.php |
| Gemini API キー | 文字起こし | https://aistudio.google.com/apikey |

### 手順

1. **このフォルダを任意の場所に展開**します。

2. **ffmpeg.exe と ffplay.exe を配置**します。
   `ffmpeg-release-essentials.zip` を解凍 → `bin\` の 2 つをプロジェクトの `ffmpeg\` にコピー。
   ```
   gemini-transcriber\
     ├─ ffmpeg\
     │   ├─ ffmpeg.exe   ← 必須
     │   └─ ffplay.exe   ← 推奨(無いと区間再生が簡易モードになります)
     ├─ src\
     ├─ build.bat
     └─ ...
   ```

3. **(任意) アイコンを置く**: `resources\icon.ico`。

4. **`build.bat` をダブルクリック** → `Output\GeminiTranscriberSetup-2.0.0.exe`。

> Inno Setup を入れずにビルドした場合は、`dist\GeminiTranscriber\` をフォルダごと
> コピーすれば動きます(ポータブル運用)。

### GitHub Actions による自動ビルド

`main` への push、または `v*` タグの push で Windows ランナー上で自動ビルドが走ります。
テスト(`tests/`)も同じジョブで実行されます。

- **PR / push**: `Actions` タブから `GeminiTranscriber-Installer` artifact をダウンロード可能
- **タグ push** (`git tag v2.0.0 && git push --tags`): 自動で Release を作成し `.exe` を添付

## トラブルシューティング

| 症状 | 対処 |
| --- | --- |
| 起動時に「ffmpeg が見つかりません」 | `ffmpeg\ffmpeg.exe` を配置して再ビルド |
| 割当画面で音が出ない | `ffmpeg\ffplay.exe` を同梱して再ビルド。画面下部に現在の再生方式が出ます |
| 「音声ファイルが見つかりません」 | 音声を移動した場合。再生ボタンから場所を指定し直せます |
| 同じ人が別のまとまりに分かれる | 声のまとまりはチャンクごとに独立です。チャンク長を延ばすと減ります |
| API キーエラー | https://aistudio.google.com/apikey で発行し、画面で「保存」 |
| 大きなファイルでアップロード失敗 | 詳細設定の「チャンク長」を短く(例: 5 分) |
| インストーラを Defender がブロック | コード署名を行うか、自己責任で除外。配布前に署名を推奨 |
