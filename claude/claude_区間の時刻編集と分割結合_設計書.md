## 0. 背景 — なぜ作るか

Gemini のタイムスタンプは実音声と局所的にずれる(既知の未修正バグ。上流での改善は見込めない)。実測(52分・520区間の実会議、ユーザーが耳で照合)では:

| 表示時刻 | 実音声とのずれ |
| --- | --- |
| 00:43:19 | 0秒(一致) |
| 00:43:51 | 約 +6秒 |
| 00:44:24 | 約 +2〜3秒 |

ずれ幅が1分足らずの間に 0→6→2 秒と変動するため、全体一律の「ずれ補正」(`Project.time_offset`)では救えない。`redistribute_times()` が救うのは「1秒刻みで詰まる」パターンだけで、この種のドリフトは対象外。よって**人が区間単位で時刻を直せるようにする**。

また、1区間に2人以上の発言が(重なりなしで)順に混ざるケースがあり、**区間の分割**が必要。転写から丸ごと落ちた発言(実測例:「OBの人」)も、隣接区間を分割して空いた側に本文を書き足せば復元できる。

ユーザー要求は3点: (1)時刻の修正 (2)発言本文の修正 (3)再生される音声の追従。
**(2)は実装済み**(右ペインの本文編集 + `text_edited` + carry-over 保護)なので触らない。(3)は時刻を直せば自動追従する設計にする。新規実装は**時刻編集(Step 1)**と**分割・結合(Step 2)**。

---

## 1. 時刻の意味論(最重要の不変量)

**`time_edited=True` の区間の `start` / `end` は「実音声の時刻」である。再生でも出力でも `time_offset` を適用しない。**

- 編集を始めるとき、その区間がまだ未編集なら、入力欄の初期値に現在の `time_offset` を織り込む(`start + time_offset` / `end + time_offset`)。ユーザーが確定した値をそのまま `start`/`end` に保存し、以後この区間は補正なしで再生・出力する。
  - 例: `time_offset=+4.0`、start=00:43:51 の区間を開くと初期値は 00:43:55.0。そのまま確定すれば「いま補正込みで聴こえている位置」がそのまま固定される。
- `orig_start` / `orig_end` は「パイプラインが出した元の時刻」(Gemini時計)を常に保持する。用途は §3 の再実行時の突き合わせ鍵と「元に戻す」。
- **元に戻す** = `start`/`end` に `orig_*` を書き戻し、`time_edited=False` に戻す(以後は再び offset が効く)。

## 3. carry-over の改修(罠がある)

`src/pipeline.py::_carry_over_assignments()` は現在**開始秒 ±2.0秒**(`MATCH_TOLERANCE_SECONDS`)で新旧を突き合わせている。ドリフト補正は最大6秒動くので、**編集後の `start` で照合すると再実行時に割当が迷子になる**。以下に変更する。

1. 引き継ぎ対象 = `speaker_id` / `text_edited` / `time_edited` のいずれかを持つ旧区間。
2. 照合鍵は **`orig_start`**(常にパイプライン時刻。キャッシュが効く限り再生成側と完全一致する)。旧ファイルでも §2 の既定値により `orig_start` は必ず埋まる。
3. 同じ `orig_start` を共有する旧区間群を**ファミリー**として扱う(分割で生まれる。§5.1)。
4. 照合できた再生成区間の処理:
   - 旧側が time_edited なし・単独 → **従来どおりフィールドコピー**(speaker_id / reviewed / note、text_edited なら text)。再生成側の時刻改善を活かす。
   - 旧側が time_edited あり、またはファミリー(2件以上) → 再生成区間を**旧区間群で丸ごと置換**する(ユーザーの時刻・構造・本文が正)。
5. 結合済み区間の吸収: time_edited の旧区間について、その `(orig_start, orig_end)` の内側に `start` が入る**未照合の再生成区間は削除**する。結合で1つにした区間が再実行で2つに戻るのを防ぐ(§5.2 で `orig_end` を後側から引き継ぐのはこのため)。
6. 最後に index を 0..n-1 で振り直す。

## 4. Step 1 — 区間の時刻編集(`assign_gui.py`)

右ペイン、区間ヘッダ(`var_seginfo`)の直下に1行追加:

```
時刻:  開始 [00:43:23.0] (−1)(−0.1)(+0.1)(+1)   終了 [00:43:27.5] (−1)(−0.1)(+0.1)(+1)   [元に戻す]
```

- 直接入力は `parse_hms()` で受ける。Enter / フォーカスアウトで反映。
- ナッジ・入力確定のたび、「移動したら自動再生」が ON なら編集後の範囲を即再生する(耳で確認するループを短くする)。
- 反映時: `time_edited=True`(初回は §1 のとおり offset を織り込んだ初期値から始める)、`_dirty=True`、`_update_row()`、タイムライン再描画、`var_seginfo` 更新。
- バリデーション: `start + 0.1 ≤ end`、`0 ≤ start`、`end ≤ duration + ε`。**隣接区間との重なりは許容する**(同時発話は正当な記録。v2 系での確立済み判断。自動で隣を詰めない)。
- 再生の変更(`play_current()`): `time_edited` の区間では (a) `shift = 0`(§1) (b) `preview_end = seg.end` — 本文長ベースの `preview_length()` を使わず、人が確認した終了時刻を尊重する。ヘッダの「(再生は先頭N秒)」表記も同様に抑止。
- 一覧の可視化: 時刻セル(`_row_values()` の `fmt_hms(seg.start)`)を time_edited なら `"✎ " + fmt_hms(seg.start)` にする。reviewed の ✓/△ と同じ「人がどこまで確認したか見える」思想。
- Undo: 既存 Ctrl+Z は割当専用のタプル形式 `(index, speaker_id, reviewed)` なので**組み込まない**。時刻の取り消しは [元に戻す] で行う。
- 入力欄フォーカス中はグローバルキー(数字キー割当・Space 再生等)を発火させないこと。本文 `txt_body` の既存の扱いに合わせる。

## 5. Step 2 — 分割・結合

### 5.1 分割ダイアログ

現在区間に「この区間を分割」ボタン。決めるのは**テキストの分割点**(カーソル位置)と**境界時刻**の2つ。

構成:

- 本文 `Text`(親の text 全文)。**カーソル位置 = テキストの分割点**。
- 波形 `Canvas`: 親区間(実時刻)±2秒を ffmpeg で PCM 抽出して描画(§5.4)。発言の切れ目は無音の谷として見えるので、**クリックで境界線を移動**できる。ffmpeg 不在時は波形なしで残りの手段だけで動くこと。
- 境界時刻: 直接入力(`parse_hms`)+ (−0.1)(+0.1) ナッジ。初期値はカーソル位置の文字数比で親区間を按分した推定値。
- [再生してマーク]: 親区間を再生し、キー押下時点の推定位置を境界に取り込む。ffplay は再生位置を報告しないため「再生開始時の `time.monotonic()` + 経過×速度」で推定する。**起動遅延で±0.2〜0.3秒程度ずれる粗マーク**であり、波形クリック・ナッジ・試聴で追い込む前提。
- [境界の前を聴く](前半末尾1.5秒)/ [境界の後を聴く](後半冒頭1.5秒)。既存 `SegmentPlayer` を共用し多重再生しない。
- OK / キャンセル。3人以上の混在は後半に対してもう一度分割すれば対応できる。

OK 時のデータ:

| | 前半 | 後半 |
| --- | --- | --- |
| 範囲 | start .. 境界 | 境界 .. end |
| text | カーソルより前 | カーソル以降 |
| cluster | **維持** | **`f"{seg.chunk}:?"`(擬似不明)** |
| speaker_id | 維持 | None |
| reviewed | **False**(範囲が変わったため聴き直し対象) | False |
| time_edited | True | True |
| orig_start / orig_end | **親の値をそのまま共有** | 同左(carry-over の系譜キー。§3-3) |
| text_edited | 立てない(機械的二分。ファミリー置換が本文も保護する) | 同左 |

後半を擬似クラスタ `?` にする理由: 元の声質ラベルは区間全体に付いたもので後半の声には保証がない。擬似クラスタは既存機構(`is_pseudo_cluster`)で**候補学習(cluster_votes)からも一括適用からも自動的に除外される**ため、分割で生まれた不確かな区間が学習を汚したり誤伝播したりすることを構造的に防げる。後半は聴いて手で確定(✓)する前提。

### 5.2 結合

「前の区間と結合」/「次の区間と結合」。分割ミスの復旧(逆操作)と、重複行の整理に使う。

- text は空白なしで連結(日本語)。読点の自動補完はしない(直後に本文編集できるため)。
- 範囲 = min(start) .. max(end)。cluster は前側を採用。
- speaker_id: 両者同一なら維持(ただし reviewed=False)。異なるなら確認ダイアログの上、None にする。
- `time_edited=True`、`orig_start` = 前側の orig_start、`orig_end` = **後側の orig_end**(§3-5 の吸収に必要)。

### 5.3 index・Treeview・Undo の宿題(設計メモの積み残し)

- 現状: iid は `f"s{seg.index}"`(`_insert_row()`)、`undo()` は `self.proj.segments[index]` を**リスト位置=index の前提**で直接参照する。
- 挿入/削除後: 全区間の index を振り直し → 既存の `reload_tree()` で再構築。`self.current` も追従させる。
- **Undo スタックの index を再マップする**(挿入位置より後は +1、削除位置より後は −1、削除された index を指す項目は結合先の index へ付け替え)。クリアで妥協しない。
- 分割・結合そのものは Ctrl+Z の対象外。逆操作(結合⇄分割)で戻す。

### 5.4 波形抽出(`audio.py`)

```python
def extract_peaks(audio_path, start, end, buckets) -> list[tuple[int, int]]
```

- `ffmpeg -ss {start} -to {end} -i ... -ac 1 -ar 8000 -f s16le -` を pipe で読み、`array('h')` にしてバケツごとの (min, max) を返す。**numpy は使わない**(main の依存に numpy は無く、増やさない)。
- 既存の `find_ffmpeg()` / `hide_console_kwargs()` を使う。ffmpeg 不在なら空リストを返し、ダイアログ側は波形なしで動く。

## 時刻欄の事故と、その後の守り【2026-08-19・実機】

### 何が起きたか

利用者が `00:35:09` を［時刻へ飛ぶ］に入れるつもりで**［開始］の欄に打った。**
`00:35:09` は時刻として正しい値なので書式の検査では止まらず、
区間ごと移動する仕組みが働いて、**15.8 秒の区間が 0〜35:25 の 2125 秒**になった。

**編集履歴が原因を教えた。**（これが編集履歴を作った意味そのもの。）

```json
{"op":"edit_time","segment":[0.0,2109.0],"before":[0.0,15.8],"after":[2109.0,2124.8]}
{"op":"edit_time","segment":[0.0,0.0],"before":[2109.0,2124.8],"after":[0.0,2124.8]}
```

`2109.0` 秒 = `00:35:09`。打った値がそのまま入っている。
**戻すのも履歴の `before` を使った**（`[0.0, 15.8]`）。

### 利用者の指摘

> この機能は、その場所に行くだけのはずなのに、どうしてデータが変更されるのですか。

**［時刻へ飛ぶ］は正しく読むだけだった**（`jump_to_time` に書き込みは無く、
その時刻が無ければ一番近い区間へ行く）。書き換えたのは［開始］の欄。
**しかし「移動するだけ」の操作の隣に「記録を変える」欄を置いた設計に責任がある。**

### 入れた守り

**ウ. 欄から離れただけでは書かない**（`<FocusOut>` で `_discard_time_edit`）

```
直す前  ent.bind("<FocusOut>", ...commit...)    通り過ぎただけで記録が変わる
直した後 ent.bind("<FocusOut>", ...discard...)  捨てて表示を元へ戻す
```

**捨てたことを黙らない。**「時刻は変えていません。変えるには Enter か
［この時刻で確認］を押してください。」と出す（打った本人は入ったつもりでいる）。

**「検証済みの記録」を売る製品で、欄を通り過ぎただけで記録が変わるのは筋が悪い。**

**イ. どの区間の欄かを見張る**（`_time_index`）

区間を移った直後に前の区間の値が入る経路。**本文欄では同じ穴を塞いだのに、
時刻欄に残っていた。**

**ア. ほかの区間をまたぐ長さは確認する**（`_confirm_wide_span`）

```
この区間の長さが 2125 秒になり、ほかの 290 区間を丸ごとまたぎます。
00:00:00.0 → 00:35:24.8
打ち間違いではありませんか?          [はい] [いいえ]  ← 既定は「いいえ」
```

- **60 秒未満の直しでは聞かない**（毎回聞かれると使えない）
- 1 区間と重なるのは相づちなどで普通に起きるので、**2 区間以上を丸ごと
  飲み込むとき**だけ聞く

3 つとも検査に落とした（書かないこと・黙らないこと・またぐと聞くこと・
短い直しでは聞かないこと）。
