# whosaid-editor GUI簡素化案 v01

作成日: 2026-09-09  
対象: `sukeko1113/whosaid-editor` main（設計時点: `9d45c70356d599710cb9f8698b89aad1e17c05f9`）  
位置づけ: **コード変更前のUI/UX設計書**。この版では実装しない。

---

## 0. 結論

現行GUIの問題は「機能が多すぎる」ことではない。必要な機能を、**通常作業・例外対応・高度設定の区別なく同じ画面に常時出している**ことが主因である。

本案では機能を捨てず、次の4原則で整理する。

1. **通常利用の流れを4段階に固定する**  
   `音声を選ぶ → 文字起こし → 話者を確認 → Word出力`
2. **初回画面には、その場で必要なものだけ出す**
3. **時刻修正・分割結合・辞書・一括修正などは「修正ツール」に退避する**
4. **詳細設定は progressive disclosure（必要なときだけ開く）にする**

目標は「初心者が説明書なしでも進める」「熟練者の機能は失わない」の両立である。

---

## 1. 製品価値から見たGUIの中心

`AGENTS.md` と `README.md` が定義している製品価値は明確である。

- AIは実名を確定しない
- A/B/C の声のまとまりを機械が作る
- 実名は人が音声を聴いて確定する
- `✓`（人が聴いて確定）と `△`（まとめて適用）を分ける
- 録音は既定ではPCの外へ出さない

したがってGUIの主役は「設定画面」ではなく、**人が音声を聴いて話者を確定していく作業**である。

現状は主画面に設定が多く、割当画面にも修復機能が常時並ぶため、この中心が見えにくくなっている。

---

## 2. 現行GUIで複雑さを生んでいる点

### 2.1 主画面 `src/gui.py`

現行主画面では、縦スクロール領域の中に次が連続している。

- 音声ファイル
- 作業フォルダ（出力先）
- 処理経路（ローカル / クラウド）
- 話者の決め方（手動 / AIにすべて任せる従来方式）
- 詳細設定
  - APIキー
  - APIキー保存
  - モデル
  - チャンク長
  - タイムスタンプ
  - 話者識別
  - 逐語モード
  - ローカル話者分離
  - キャッシュを使わずやり直す
- 出席者
- 開始 / キャンセル / 出力先を開く / ライセンス表示
- 進捗
- ログ

実装コメントにも「中身は縦に長い」「画面が足りないので主画面をスクロールさせる」とある。

これは高度設定を持つアプリとしては合理的だが、初見利用者には「まず何をすればよいか」が弱くなる。

### 2.2 話者割当画面 `src/assign_gui.py`

割当画面では、主目的の話者確定に加え、次が同時に見えている。

- 進捗
- タイムライン
- 絞り込み4種
- 聴く順
- 時刻へジャンプ
- 全区間一覧
- 区間開始・終了時刻の直接編集
- ±1 / ±0.1 秒調整
- 区間全体スライド
- 時刻確認 / 元に戻す
- 分割 / 前と結合 / 次と結合 / 削除
- 発話追加
- 本文編集
- 再生 / 5秒前 / 速度 / 30秒先
- 全体ずれ補正
- 話者候補
- 同一クラスタ一括適用
- 自動次送り
- 足した発言の表示方法
- 不明 / 未確定へ戻す / Undo
- 出席者編集
- 残作業一覧
- 語句一括修正
- 語句Undo
- 話者一括置換
- クラスタを未確定へ戻す
- 時刻点検
- 一括適用Undo
- 保存
- 元音声照合
- Word出力

これらの多くは必要な機能である。ただし、**1区間を聴いて話者を決める瞬間には不要なものが大半**である。

### 2.3 実機で起きた問題が「足す・分ける」を増やしてきた

近いコミットとコードコメントには、次のような実機問題が繰り返し記録されている。

- 右端のボタンが切れる
- 下の保存ボタンが隠れる
- 候補者が途中までしか見えない
- 1行に詰めると1280×720 / 125%等で収まらない
- 1024×768 / 125%でダイアログが画面幅からはみ出す

その都度、行を分けたり注記を別行にしたりして安全性を確保してきた。これは正しい修正だったが、積み上がった結果、**画面全体としては情報密度が高くなった**。

次の段階では「さらに並べ直す」のではなく、**普段は出さない**という構造変更が必要である。

## 3. 新しい全体フロー

### 通常利用者に見せる流れ

```text
[1 音声を選ぶ]
      ↓
[2 文字起こしを開始]
      ↓
[3 話者を確認する]
      ↓
[4 Wordに出力]
```

出席者登録は 1 と 2 の間に「任意」として置く。

設定値の大半は既定値を使い、現在の設定だけを1行で要約する。

例:

```text
処理: このPC / 標準 / 声のまとまりを作る / 音声と同じフォルダ
                                                [変更]
```

## 4. 主画面の新設計

## 4.1 通常状態

初回表示は、縦スクロールを原則不要にする。

```text
┌────────────────────────────────────────────┐
│ Whosaid 反訳エディタ                       │
│ 音声を選び、話者を確認してWordにまとめます │
├────────────────────────────────────────────┤
│ 1. 音声ファイル                            │
│ [ 音声ファイルを選ぶ... ]                  │
│  selected_meeting.mp3   67分               │
│                                            │
│ 2. 出席者（任意）                          │
│  6人登録済み                     [編集...] │
│  ※未入力でも開始できます                   │
│                                            │
│ 処理: このPC / 標準 / 話者分離ON           │
│ 出力: 音声と同じフォルダ          [設定...] │
│                                            │
│          [ 文字起こしを開始 ]              │
│                                            │
│ [保存済みの作業を続きから開く...]          │
└────────────────────────────────────────────┘
```

### 常時表示するもの

- 音声選択
- 出席者の人数と編集入口
- 現在の主要設定の要約
- 大きな開始ボタン
- 保存済み作業を開く

### 常時表示しないもの

- APIキー
- APIキー保存方法
- モデル詳細
- チャンク長
- タイムスタンプ
- 逐語モード
- キャッシュ強制破棄
- 詳細ログ
- ライセンス一覧

これらは削除せず、設定画面または処理中詳細へ移す。

---

## 4.2 「設定...」を開いたとき

設定は1つの長い表ではなく、用途で分ける。

### A. 処理

- `このPCで処理（推奨）`
- `クラウド Gemini を使う`

ローカル時だけ:

- モデル: 標準 / 高精度
- 声のまとまりを作る: ON（既定）

クラウド時だけ:

- APIキー
- APIキーの保存有無
- Geminiモデル
- 逐語モード

**無効な設定を灰色で大量に残すより、そもそも表示しない。**

### B. 保存先・出力

- 音声と同じフォルダ
- 別の作業フォルダ
- タイムスタンプ等の出力オプション

### C. トラブル時

- キャッシュを使わず最初からやり直す
- モデル再取得等の診断入口

通常利用者が誤って触る必要がない設定をここに隔離する。

---

## 4.3 「AI にすべて任せる（従来方式）」の扱い

通常画面から外すことを推奨する。

理由:

1. 現在の製品価値は「実名は人が音声を聴いて確定」
2. README / AGENTS の説明と、主画面の選択肢が同時に見えると初見利用者には矛盾に見える
3. ローカル経路では使えず、無効状態と注記が増えている
4. 互換機能として残すことと、通常利用者に常時見せることは別

当面は削除せず、

`設定... → 互換・従来機能 → AIに実名推定を任せる（クラウドのみ）`

へ退避する。

将来、利用実績がほぼ無ければ廃止を別判断する。

---

## 4.4 処理中画面

処理開始後は主画面の設定群をそのまま残さず、状態を中心にする。

```text
文字起こし中
████████████████░░░  72%

現在: 話者分離を処理しています

[キャンセル]
[処理の詳細 ▼]
```

`処理の詳細` を開いたときだけログを表示する。

正常利用者にログを常時見せない。エラー時には自動で開いてよい。

## 5. 話者割当画面の新設計

## 5.1 通常作業モード

画面の中心を「聞く → 選ぶ → 次へ」に絞る。

```text
┌───────────────────────────────────────────────────────────────┐
│ 確認 156/412   ✓聴いて確定 43   △まとめて適用 113          │
│ ████████████░░░░░░                               [修正ツール]│
├──────────────────────┬────────────────────────────────────────┤
│ すべて / 未確認      │  00:12:38  声B                       │
│                      │                                        │
│ 12:31 A 佐藤 …       │ 「それでは次の議題に移ります…」       │
│ 12:38 B ?   …        │                                        │
│ 12:45 A 佐藤 …       │ [▶ 再生 Space] [5秒前] 速度 1.0x      │
│                      │                                        │
│                      │ 話者を選ぶ                             │
│                      │ [1 佐藤]                               │
│                      │ [2 田中]                               │
│                      │ [3 鈴木]                               │
│                      │                                        │
│                      │ ☑ 同じ声にもまとめて適用              │
│                      │                                        │
│                      │ [不明]                [取り消し]       │
├──────────────────────┴────────────────────────────────────────┤
│ 自動保存済み                 [保存]   [Wordに出力...]        │
└───────────────────────────────────────────────────────────────┘
```

### 通常作業で残すもの

- 進捗と `✓ / △`
- 区間一覧
- 現在の本文
- 再生
- 5秒前から
- 再生速度
- 話者候補
- 同一声クラスタへの一括適用
- 不明
- Undo
- 保存
- Word出力

`同じ声のまとまり全体に適用` はこの製品の作業時間を大きく減らす中心機能なので、**隠さない**。

`✓ / △` も製品価値そのものなので、常に見せる。

---

## 5.2 通常画面から「修正ツール」へ移すもの

右上の `[修正ツール]` を押したときだけ表示する。

### 区間・時刻

- 開始時刻 / 終了時刻
- ±0.1 / ±1 秒
- 区間全体スライド
- この時刻で確認
- 時刻を元に戻す
- 全体ずれ補正
- 時刻点検

通常利用時は `時刻を直す...` という1つの入口にまとめる。

### 区間構造

- 分割
- 前と結合
- 次と結合
- 追加発話
- 追加区間を削除

`区間を修正...` という1つの入口にまとめる。

### 一括修正

- 語句をまとめて直す
- 直した語句を戻す
- 話者をまとめて置き換える
- このまとまりを未確定に戻す
- 一括適用を取り消す

`一括修正...` にまとめる。

### 管理

- 出席者を編集
- 残作業一覧
- 元音声と照合
- 辞書管理

上部の `…` または `管理` メニューへ移す。

---

## 5.3 表示設定へ移すもの

- `確定したら次へ`
- `足した発言も行で出す`
- `聴く順`
- `別の声あり`
- その他の一覧フィルタ

初期値は現在の推奨値を使う。

通常作業では、一覧上部を

`[すべて] [未確認]   [表示 ▾]`

程度にする。

`時刻へ飛ぶ` は `[表示 ▾]` ではなく、一覧検索/ジャンプの小さな入口として残してもよい。700区間級では必要性が実機で確認されているため、機能自体は削らない。

---

## 5.4 キーボード操作

ショートカットは残す。ただしすべてを画面上に文字で並べない。

常時見せる:

- `Space` 再生
- 候補ボタンの `1, 2, 3...`
- Undo の `Ctrl+Z`

ヘルプへ移す:

- J/K
- A
- D
- Shift+矢印
- Tab / Shift+Tab

熟練者の速度を落とさず、初心者の情報量を減らす。

## 7. 画面サイズの受入基準

最近の実機履歴を踏まえ、UI変更は「部分が見える」ではなく**四辺すべてが収まること**で確認する。

最低確認条件:

- 1024×768 / Windows拡大率125%
- 1280×720 / 125%
- 1366×768 / 150%
- 1920×1080 / 100% または 125%

### 主画面

- 初期状態で縦スクロール不要
- 開始ボタンが常時見える
- 音声選択から開始まで視線が上→下に一本道

### 割当画面

- 話者候補が最低3人以上見える
- 再生・候補・一括適用・Word出力がウィンドウ拡大なしで届く
- 高度な修正ツールを閉じた状態で主要操作が全部見える
- 右端・下端のボタンが欠けない

## 8. Astra / Computer Use で行うユーザーテスト

この設計はコードレビューから作ったもので、**まだ実アプリをAstraに操作させた結果ではない**。

実装前後で、同じタスクを使って比較する。

### テストタスク

1. 初めて起動する
2. MP3を選ぶ
3. 出席者を6人登録する
4. ローカル既定設定で文字起こしを開始する
5. 最初の5区間の話者を確定する
6. 1区間の本文を直す
7. 1区間だけ時刻を微調整する
8. Wordへ出力する
9. アプリを閉じ、保存済み作業を再開する

### 記録する指標

- タスク完了率
- 間違ったクリック
- 「次に何をするか」迷った箇所
- 3秒以上止まった箇所
- スクロール回数
- ダイアログを閉じてやり直した回数
- 高度設定を誤って触った回数
- 文字起こし開始までのクリック数
- 最初の5区間確定までのクリック数
- Word出力までのクリック数

### Astraへの指示例

```text
このアプリを初めて使う一般ユーザーとして操作してください。
開発者の知識は使わないでください。

音声ファイルを読み込み、出席者6人を登録し、ローカルの既定設定で
文字起こしを開始してください。その後、最初の5区間について音声を聴き、
話者を確定してください。1区間の本文を修正し、別の1区間の時刻を微調整し、
最後にWordへ出力してください。

各工程で、次に何を押すか迷った箇所、意味が分からない表示、不要だと思った設定、
誤クリック、スクロール回数、クリック数を記録してください。
コードは変更しないでください。
```

## 9. 実装順序

`AGENTS.md` の「小さい単位で変更・各単位でテスト」に合わせ、まとめて作り替えない。

### Phase 1: 主画面だけ簡素化

- 詳細設定を折りたたみ/別ダイアログへ移す
- 通常画面を `音声 / 出席者 / 設定要約 / 開始 / 続きから` に絞る
- 処理ログを折りたたむ
- データ構造・パイプラインは変更しない

**最初にここだけ実装して実機確認する。**

### Phase 2: 割当画面に「通常作業モード」を作る

- 時刻修正・区間修正を閉じる
- 候補と再生を中心にする
- 既存機能は消さず「修正ツール」で開く

### Phase 3: 下部ツール群を整理

- 一括修正
- 管理
- 表示設定

へ分類してまとめる。

### Phase 4: 従来AI方式の扱いを決める

- 互換設定へ移した状態で利用実績を確認
- 廃止は別判断。GUI簡素化と同時に削除しない

## 10. 実装で壊してはいけないもの

GUIを簡単にしても、次は絶対に変えない。

- `reviewed` の意味
  - `✓` = 人が耳で聴いて確定
  - `△` = 一括適用のみ
- 自動処理が `✓` を立てない
- `speaker_id` を名簿編集で振り直さない
- 相づちを自動削除しない
- 音声指紋アルゴリズムを変えない
- 利用者が明示したクラウド処理以外に音声・本文を送信しない
- ローカルを既定にする
- 作業ファイルの自動保存・再開性を失わない

UI変更は**表示と導線の変更**に限定し、意味論・保存形式・転写結果を同時に変えない。

## 13. 最終判断

現状のGUIは、機能単位ではかなり丁寧に作られている。問題は、丁寧に追加された機能がすべて同時に見えるようになったことにある。

したがって「機能を削る」再設計ではなく、

> **初心者には一本道、必要な人には奥に全部ある**

という二層構造が最も適している。

特に主画面は、`音声を選ぶ → 開始` までを短くするだけで印象が大きく変わる。割当画面は「時刻や区間を直す専門エディタ」と「毎区間の話者確認」を同時表示しないだけで、操作密度を大幅に下げられる。

次の実装単位は **Phase 1（主画面の簡素化のみ）** とし、割当画面にはまだ触れないことを推奨する。
