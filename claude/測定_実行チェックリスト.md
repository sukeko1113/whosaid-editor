**v1 からの変更: 出力先の順序を交互にしました。** 理由は §0 を読んでください。

---

## 0. なぜ順序を交互にするのか

v1 は G1 を3回続けてから C2 を3回でした。**この順だと、出力先の差と実行順の差が
混ざります。**

2時間近く連続で GPU を回すので、後半ほど機械が温まります。サーマルスロットリングが
あれば、あとに回した C2 が遅く出るのは当然です。**そうなると「G ドライブのほうが速い」
という結論が、実は「先に測ったほうが速い」だっただけ、ということになります。**

交互にすれば、順序の影響が両方に均等にかかります。

```
G1 → C2 → G1 → C2 → G1 → C2 → C3
```

出力先を毎回切り替えるので手順は面倒ですが、**結論の正しさのほうが重要です。**

## 各回に共通の手順

**すべての回で、この6ステップを踏みます。**

### ステップ1 — キャッシュを消す

```powershell
cd C:\dev\01\whosaid-editor
.venv\Scripts\python.exe tools\clear_run_cache.py "<その回の出力先>"
```

一覧が出たら `y`。**削除件数を見てから進む。**
「消すものがありません」なら既に消えているので、そのまま進んで構いません。

### ステップ2 — アプリを起動

```
C:\dev\01\whosaid-editor\dist\WhosaidEditor\WhosaidEditor.exe
```

### ステップ3 — 設定

- 音声: `01+02edited.wav`
- 出力先: **その回のもの（毎回変わります）**
- モデル: その回のもの
- 話者分離: **ON**
- チャンク長: **7分**
- 出席者: **7回とも同じ**（消えていたら入れ直す）

### ステップ4 — 開始 → ログの最初を見る

`処理経路: ローカル(モデル small)` または `(モデル large-v3)` が意図どおりか。
**違ったら止めて設定し直す。**

作業ファイルのパスも出るので、**出力先が合っているかも同時に確認できます。**

### ステップ5 — 待つ

標準で約17分、高精度で約32分。放置して構いません。

### ステップ6 — ログを保存

ログ欄を全選択してコピーし、テキストファイルに保存。

**G1 の回だけ、そのあと Google ドライブの同期完了を待ってください。**
タスクトレイのアイコンが止まってから次へ。

# 途中で止まったとき

**キャッシュを消し忘れた回**は、そのログを捨てて、消してから回し直してください。

**出力先やモデルを間違えた回**も同じです。捨てて回し直します。

**中断した回**は、ログを保存せずに捨ててください。中途半端なログを混ぜると
集計が読めなくなります。

**回し直したときは、順序が崩れることを Claude Code に伝えてください。**
交互にしている意味が薄れるので、集計のときに考慮が要ります。

# 測定の結果にかかわらず

**作業ファイルを Google ドライブなどの同期フォルダに置くと、音声も本文もクラウドに
アップロードされます。** ローカル完結を売りにしているアプリで、倫理審査や守秘義務が
理由で使う利用者がいる以上、**速さでは推奨を決められません。**

この測定は「どちらが速いか」を測るものであって、「どちらを推奨するか」は別の話です。
