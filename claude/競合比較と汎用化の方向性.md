## 結論

- **優位性はある。ただし「文字起こしアプリとして」ではなく「話者確定の工程を人の手に返した設計」として。**
- **汎用化するなら方向は「万人向け議事録アプリ」ではなく「話者確定エディタの入出力を選ばなくする」。** 前者は Teams / Zoom / Meet の無料機能に侵食された飽和市場、後者は空白地帯。

---

## 1. 市場の前提（調査で確認できた事実）

### 話者分離の精度は原理的に頭打ち

| 条件 | DER の目安 |
| --- | --- |
| クローズドマイク・2〜4人・重なり少 | 8% 未満 |
| AMI（全員ヘッドセット）ベンチ | pyannote 3.1 で約 11% |
| 重なり率 10〜20%（通常の会議） | 20〜35% |
| 残響・似た声・重なり多 | AMI比 +5〜15pt |

pyannote 最新の無料モデル `community-1` でも AliMeeting 20.3% / AMI IHM 17.0% / DIHARD3 20.2%。
NVIDIA Sortformer は 4話者までなら DER 13.24% だが 5話者以上で 42.56% に崩壊、かつ「非英語では性能が落ちうる」と明記。

**日本語会議音声の公開 DER はほぼ存在しない。** 数少ない検証（WeSpeaker/ECAPA、日本語14話者468秒）は **DER 64.91〜82.80%** と実用外だった。

→ **卓上マイク1本・日本語の会議で、AI に実名まで当てさせる方式は原理的に成立しない。** v1.3 で体験した通り。

### 誤りの中でも「話者取り違え」が最悪

pyannoteAI は Confusion（誰の発言かの取り違え）を、利用者体験にとって最も損害の大きい誤りの種類と位置づけている。転写が読み手を誤らせるためである。
文字の誤変換と違い、**読んだだけでは誤りと気づけず、必ず音声に戻って照合が要る。**
テープ起こし業者の記事も「話者照合は会議出席者にしかできない」と述べており、AI に外部化できない工程が構造的に残る。

### ユーザーの不満は「誤ること」より「直せないこと」

ITreview の Notta レビューに「複数人が話す場面では話者の識別が時々入れ替わるため、後から修正する際に一括編集機能（が欲しい）」。
求められているのは精度向上ではなく**修正手段**。

### 声紋登録は法務リスクを負っている

AI GIJIROKU / AmiVoice ScribeAssist / Teams Rooms は声紋登録を持つが、
Microsoft Teams の diarization は**イリノイ州 BIPA 違反で提訴中**（争点：話者分離で抽出する声のベクトルを氏名に紐づける行為は実質的な声紋収集にあたる）。
Microsoft はイリノイ州で voice enrollment を完全ブロックしている。

### 既存 OSS が届いていない範囲

- **noScribeEdit**（faster-whisper + pyannote、専用エディタ同梱）— 日本語は品質保証対象外と明記
- **OpenTranscribe**（WhisperX + pyannote v4、声紋によるファイル横断の話者同定、AI推定を信頼度付きで accept/reject）
- **Buzz / Vibe** — 話者分離は限定的
- **ELAN / Praat / Label Studio** — 研究用汎用ツール。RTTM/JSON の取り込みは自前スクリプトが要る。日本語UIなし

いずれも**人が直せるのはテキスト側の話者名まで**。「クラスタをマージ／スプリットする」という diarization 誤りの本丸を触る操作はない。

## 2. 本アプリの優位性

> この節の実装に関する記述は 2026-07-31 時点のものである。
> 現状との差は冒頭の表を参照。**論点そのものは有効。**

### 効いているもの

1. **「AI は A/B/C に分けるだけ、実名は人が確定」という設計方針**
   競合は全部逆方向（AI に実名まで当てさせる）。DER の実態を踏まえると、この方針転換自体が正しい。
   v1.3 → v2.0 の変更は、市場が構造的に抱えている問題を先回りで解いている。

2. **`reviewed` フラグ（✓ / △）— 調べた範囲で唯一無二**
   「自分の耳で聴いた」と「一括適用で埋めただけ」の区別。
   逐語録が求められる現場（議会・監査・法務・研究）では、**検証済みであることの担保**が成果物の価値そのもの。
   競合・OSS のどれにもこの概念がない。

3. **候補の学習と伝播**
   クラスタ投票100 / チャンク境界の連続性45 / 遷移25 / …という重み付け、仮ラベルの自動伝播、確信度ゲート、未知の声の outlier フラグ。
   「人の判断は実質 話者数 × チャンク数」まで圧縮している。noScribeEdit も OpenTranscribe もここまで踏み込んでいない。

4. **声紋を永続保存しない**
   セッション内クラスタ + 事後の人手ラベル確定。BIPA 型の法務リスクを構造的に踏まない。
   声紋登録型の競合に対する、精度ではなく**制度上の**優位。

5. **`redistribute_times()`**
   Gemini のタイムスタンプ問題は**既知の未修正バグ**として報告されている（Gemini 3 Flash / 3.1 Pro で進行性ドリフト、11分49秒で -157秒。2026年5月時点で Google からの公式回答なし）。
   Simon Willison も市議会音声3時間の処理で「タイムスタンプが実音声と合わない」と報告。
   Gemini 音声 API を使う限り誰もが踏む地雷を、按分アンカー方式で既に解いてある。**これは再実装コストの高い資産。**

6. **コスト**
   Gemini 音声入力は 1時間あたり約 $0.035〜0.12。外注のテープ起こしは音源1分 98〜200円（1時間 5,880〜12,000円）。**3〜4桁違う。**

7. **短い相づちを消さない判断**
   逐語録用途では正しい判断。汎用議事録ツールは逆（要約優先で削る）ため、逐語が要る現場では差別化になる。

### 効いていない／弱いもの

- **文字起こし精度そのもの**は Gemini 依存で差別化なし
- **声質特徴量が MFCC 42次元の自前実装** — ECAPA ベースの WeSpeaker ですら日本語14話者で DER 65〜83% という報告がある。合成音声3話者での「1件教えれば残り100%的中」が実会議に外挿できるとは考えにくい。**実会議での検証が未実施**（設計メモ自身が認めている通り）— ここが汎用化の前提条件
  （**追記: この 2 点はいずれも解消済み。** sherpa-onnx への置き換えと、67 分の実会議音声による測定が完了している）
- **配布の摩擦** — インストーラ、API キーの取得、ffmpeg 依存
- **個人開発である信頼性** — 自治体は調達フローに乗せられない
- **「一括修正」は toruno などが既に実装済み** — ここ単体では差別化にならない

### 補足（2026-07-31 時点の状況・現在は解消済み）

`feature/manual-speaker-assignment`（cluster_only + Tkinter 割当エディタ）と
`feature/manual-speaker-labeling`（webapp + `features.py` の声質特徴量）が並走している。
汎用化の前にどちらを本線にするかの決着が要る。

## 3. 汎用化と需要

> **指示書 §3・§9-2 が参照しているのはこの節である。**

### やってはいけない汎用化

**「誰でも使える議事録アプリ」への一般化。** Notta / スマート書記 / AmiVoice / YOMEL に加え、
Teams・Zoom・Meet が会議ツール自体に文字起こしと要約を無料で内蔵している。
汎用議事録の市場は「無料でついてくるもの」に侵食済みで、個人開発が正面から入る余地はない。

### 勝ち筋の汎用化 — 「話者確定の工程だけを切り出す」

いま Gemini 出力に閉じている入出力を、フォーマット非依存にする。

**入力を増やす**
- pyannote の RTTM
- WhisperX / faster-whisper の JSON
- Whisper の SRT / VTT
- OpenAI `gpt-4o-transcribe-diarize` の出力
- 各社 SaaS のエクスポート（Notta の SRT など）

`segments.py` が既に転写テキスト・SRT・JSON の取り込みを持っているので**素地はある**。

**出力を増やす**
- docx / txt に加えて SRT / VTT / RTTM / JSON

こうすると立ち位置が「**文字起こしは好きなもので、話者確定だけこれ**」になる。
Notta 等と競合せず**補完**になり、既存ツールのユーザーがそのまま流入経路になる。

**さらに一歩**
- CLI / ライブラリとして呼べるようにする（GUI は薄い皮に）
- 話者確定エディタ単体を OSS として切り出す

### 需要のある層（濃い順）

1. **自治体・議会の会議録**
   山梨県の調査で年間 7,305時間・1,450万円（庁内作成分のみ、外注は対象外）。
   作成形式は概要抜粋 56% / **逐語 30%** / 発言メモ 13%。この逐語 30% が話者確定コストを最も強く負っている層。
   AmiVoice が自治体400件超（全自治体の 1/5 以上）を押さえているので**正面からの調達は無理**。
   → **テープ起こし業者側にツールを渡す**ほうが現実的。会議録研究所は AmiVoice の販売代理店も兼ねており、業者自身が AI を工程に取り込んでいる。

2. **質的研究者・インタビュー逐語録**
   ELAN / Praat を使っているが日本語UIなし・文字起こしと非統合。
   **ローカル完結＝倫理審査を通しやすい**のが決定的に効く。クラウド送信必須のサービスは審査で落ちる。
   ここが一番、金額は小さいが刺さり方が深い。

3. **士業・法務**（証拠としての逐語録）、**医療面接**、**記者**
   `reviewed` フラグの価値が最も高い層。

4. **テープ起こし業者そのもの**
   音源1分 98〜200円の単価構造。工程短縮がそのまま利益になる。

### 現実的なマネタイズ

個人開発のデスクトップアプリを日本の法人に直販するのは難しい。順序としては

1. **OSS として出す**（英語 README 付き。日本語会議・Gemini 前提の話者確定エディタは調べた範囲で存在しない）
2. 評判ができてから、**業者・研究室からの受託／カスタマイズ**
3. あるいは Windows インストーラ付きの**買い切り数千円**

「精度より、誰が言ったかの確定と検証コストが問題」という論点は、**日本語圏で正面から扱った記事がほぼ見当たらない言説上の空白地帯**。この主張を書いて出すこと自体が差別化になる。

### 効いているもの

1. **「AI は A/B/C に分けるだけ、実名は人が確定」という設計方針**
   競合は全部逆方向（AI に実名まで当てさせる）。DER の実態を踏まえると、この方針転換自体が正しい。
   v1.3 → v2.0 の変更は、市場が構造的に抱えている問題を先回りで解いている。

2. **`reviewed` フラグ（✓ / △）— 調べた範囲で唯一無二**
   「自分の耳で聴いた」と「一括適用で埋めただけ」の区別。
   逐語録が求められる現場（議会・監査・法務・研究）では、**検証済みであることの担保**が成果物の価値そのもの。
   競合・OSS のどれにもこの概念がない。

3. **候補の学習と伝播**
   クラスタ投票100 / チャンク境界の連続性45 / 遷移25 / …という重み付け、仮ラベルの自動伝播、確信度ゲート、未知の声の outlier フラグ。
   「人の判断は実質 話者数 × チャンク数」まで圧縮している。noScribeEdit も OpenTranscribe もここまで踏み込んでいない。

4. **声紋を永続保存しない**
   セッション内クラスタ + 事後の人手ラベル確定。BIPA 型の法務リスクを構造的に踏まない。
   声紋登録型の競合に対する、精度ではなく**制度上の**優位。

5. **`redistribute_times()`**
   Gemini のタイムスタンプ問題は**既知の未修正バグ**として報告されている（Gemini 3 Flash / 3.1 Pro で進行性ドリフト、11分49秒で -157秒。2026年5月時点で Google からの公式回答なし）。
   Simon Willison も市議会音声3時間の処理で「タイムスタンプが実音声と合わない」と報告。
   Gemini 音声 API を使う限り誰もが踏む地雷を、按分アンカー方式で既に解いてある。**これは再実装コストの高い資産。**

6. **コスト**
   Gemini 音声入力は 1時間あたり約 $0.035〜0.12。外注のテープ起こしは音源1分 98〜200円（1時間 5,880〜12,000円）。**3〜4桁違う。**

7. **短い相づちを消さない判断**
   逐語録用途では正しい判断。汎用議事録ツールは逆（要約優先で削る）ため、逐語が要る現場では差別化になる。

### 効いていない／弱いもの

- **文字起こし精度そのもの**は Gemini 依存で差別化なし
- **声質特徴量が MFCC 42次元の自前実装** — ECAPA ベースの WeSpeaker ですら日本語14話者で DER 65〜83% という報告がある。合成音声3話者での「1件教えれば残り100%的中」が実会議に外挿できるとは考えにくい。**実会議での検証が未実施**（設計メモ自身が認めている通り）— ここが汎用化の前提条件
  （**追記: この 2 点はいずれも解消済み。** sherpa-onnx への置き換えと、67 分の実会議音声による測定が完了している）
- **配布の摩擦** — インストーラ、API キーの取得、ffmpeg 依存
- **個人開発である信頼性** — 自治体は調達フローに乗せられない
- **「一括修正」は toruno などが既に実装済み** — ここ単体では差別化にならない

### 補足（2026-07-31 時点の状況・現在は解消済み）

`feature/manual-speaker-assignment`（cluster_only + Tkinter 割当エディタ）と
`feature/manual-speaker-labeling`（webapp + `features.py` の声質特徴量）が並走している。
汎用化の前にどちらを本線にするかの決着が要る。

## 3. 汎用化と需要

> **指示書 §3・§9-2 が参照しているのはこの節である。**

### やってはいけない汎用化

**「誰でも使える議事録アプリ」への一般化。** Notta / スマート書記 / AmiVoice / YOMEL に加え、
Teams・Zoom・Meet が会議ツール自体に文字起こしと要約を無料で内蔵している。
汎用議事録の市場は「無料でついてくるもの」に侵食済みで、個人開発が正面から入る余地はない。

### 勝ち筋の汎用化 — 「話者確定の工程だけを切り出す」

いま Gemini 出力に閉じている入出力を、フォーマット非依存にする。

**入力を増やす**
- pyannote の RTTM
- WhisperX / faster-whisper の JSON
- Whisper の SRT / VTT
- OpenAI `gpt-4o-transcribe-diarize` の出力
- 各社 SaaS のエクスポート（Notta の SRT など）

`segments.py` が既に転写テキスト・SRT・JSON の取り込みを持っているので**素地はある**。

**出力を増やす**
- docx / txt に加えて SRT / VTT / RTTM / JSON

こうすると立ち位置が「**文字起こしは好きなもので、話者確定だけこれ**」になる。
Notta 等と競合せず**補完**になり、既存ツールのユーザーがそのまま流入経路になる。

**さらに一歩**
- CLI / ライブラリとして呼べるようにする（GUI は薄い皮に）
- 話者確定エディタ単体を OSS として切り出す

### 需要のある層（濃い順）

1. **自治体・議会の会議録**
   山梨県の調査で年間 7,305時間・1,450万円（庁内作成分のみ、外注は対象外）。
   作成形式は概要抜粋 56% / **逐語 30%** / 発言メモ 13%。この逐語 30% が話者確定コストを最も強く負っている層。
   AmiVoice が自治体400件超（全自治体の 1/5 以上）を押さえているので**正面からの調達は無理**。
   → **テープ起こし業者側にツールを渡す**ほうが現実的。会議録研究所は AmiVoice の販売代理店も兼ねており、業者自身が AI を工程に取り込んでいる。

2. **質的研究者・インタビュー逐語録**
   ELAN / Praat を使っているが日本語UIなし・文字起こしと非統合。
   **ローカル完結＝倫理審査を通しやすい**のが決定的に効く。クラウド送信必須のサービスは審査で落ちる。
   ここが一番、金額は小さいが刺さり方が深い。

3. **士業・法務**（証拠としての逐語録）、**医療面接**、**記者**
   `reviewed` フラグの価値が最も高い層。

4. **テープ起こし業者そのもの**
   音源1分 98〜200円の単価構造。工程短縮がそのまま利益になる。

### 現実的なマネタイズ

個人開発のデスクトップアプリを日本の法人に直販するのは難しい。順序としては

1. **OSS として出す**（英語 README 付き。日本語会議・Gemini 前提の話者確定エディタは調べた範囲で存在しない）
2. 評判ができてから、**業者・研究室からの受託／カスタマイズ**
3. あるいは Windows インストーラ付きの**買い切り数千円**

「精度より、誰が言ったかの確定と検証コストが問題」という論点は、**日本語圏で正面から扱った記事がほぼ見当たらない言説上の空白地帯**。この主張を書いて出すこと自体が差別化になる。
